Workflows

Every workflow is two choices: how you create content (visually or with AI) and how you publish it into Canvas (paste, package import, or API). Pick one of each — and change your mind anytime.

Step 1 · Create

Two ways to make course content

Both methods produce the same thing — Canvas-safe pages and assignments as small text files in a course folder — so this isn't a fork in the road. Start with whichever fits how you like to work, and mix them freely.

Visual Canvas DesignerAI Agent + SKILL.md
You work byClicking blocks together, editing text in placeDescribing what you want in plain language
Best atPrecise control, quick edits, seeing exactly what you'll getGenerating lots of content fast, bulk changes, working from rough notes
NeedsThe free Mac app, or Python 3 for the script versionAny AI chat (free tiers work), or an AI coding tool for whole courses
AI involved?None — fully local and deterministicYes — that's the point
They're teammates, not rivals. A common pattern: an agent drafts the semester from your notes, and you polish pages in the Designer — or you design one page you love and ask the agent to repeat its structure for every week.
Create · Visual

Canvas Designer — the visual editor

Canvas Designer looks and feels like the Canvas page editor, with three important upgrades: every block you insert is guaranteed to survive the Canvas sanitizer, your whole course is open at once (not one page at a time), and assignment settings live in a form beside the content instead of scattered Canvas menus.

Steps

  1. Download the Mac app and drag it to Applications — or, on any platform, run python3 tools/designer.py . inside a course folder.
  2. Create a new course from the welcome screen (it scaffolds the folder for you) or open an existing course folder.
  3. Build pages from the element palette: click a page, insert blocks, edit text in place, switch themes, save.
  4. For assignments, fill in the settings form — points, due date, submission type, grading, group.
  5. Click Build to produce the .imscc import package, then publish with Publish path 2.

Full feature tour on the Designer page.

Create · AI

AI agent — describe it, review it

The AI method comes in two sizes:

Web chat — single pages, zero setup

Best for a first try, workshops, and one-off pages.

  1. Paste the contents of SKILL.md into Microsoft Copilot, ChatGPT, or Claude (or upload the file). It opens with instructions that tell the AI what to do; wait for its ready message.
  2. Paste your course content — rough notes are fine — plus any style preferences.
  3. Copy the HTML source it produces and publish with Publish path 1.

Coding agent in a course folder — whole courses

For actually building and managing a course, open a course folder in an AI coding tool (Claude Code, Cursor, VS Code + Copilot). The folder's included instructions teach the agent the rules automatically, and you work in plain language:

"Set up style.md for a warm, approachable studio course."
"Create class pages for weeks 1-12 from my notes in notes.txt."
"Add Project 1: 100 points, letter grade, PDF upload, due Oct 7."
"Shift every due date after reading week one week later."

The agent writes one file per page and assignment; you review the changes, then build and publish with Publish path 2 (or push single edits with path 3).

The shared foundation

The course folder both methods share

Designer and agent meet in the middle: a folder of small, readable text files — one per page, one per assignment, plus your grading scheme, module structure, and course style. The folder, not Canvas, is the source of truth:

  • Consistency for free — your theme, colors, and recurring sections are saved in the folder (style.md, and styles.json for Designer-made custom styles), so everything you or an agent creates matches.
  • Course-wide edits are cheap — an agent can edit fifty files from one sentence, and the Designer's theme switch restyles a page in one click.
  • History and reuse — keep the folder in git for a record of every change; next semester is a copy of the folder with new dates.

Start from the template

The canvas-course-template repository is a ready-made course folder: build tools, the skill file, agent instructions, a fillable style.md, and starter content. Three ways to get one:

  • Canvas Designer: "New course" on the welcome screen scaffolds the same structure — no GitHub needed.
  • On GitHub (recommended for history and backup): click "Use this template" on the template repo, name it for your course, and clone it.
  • Without an account: download the ZIP, or run npx degit npuckett/canvas-course-template my-course.
No coding required. The files are short and readable — settings at the top, page content below. The Designer edits them visually, agents edit them from plain language, and you can always open them in any text editor.
Step 2 · Publish

Which publish path should I use?

However you created the content, there are three ways to get it into your Canvas course. They differ in how much each trip carries and what your school lets you do.

PathCarriesSetup neededBest for
1. Copy & paste One page or assignment description at a time. No settings — points and due dates are still clicked in Canvas. None Single pages, quick fixes, web-chat outputs, workshops
2. Package import Everything at once: all pages, all assignments with points, due dates, submission types, and grading; weighted assignment groups; modules; syllabus; home page. None — uses the Import button teachers already have Whole courses, restructures, next semester's shell, bulk updates. The Designer's Build button and the agent workflow both target this path.
3. API sync Pages, assignments, and syllabus — pushed instantly, no import step. A Canvas access token (some schools disable these — see below) Day-to-day edits after the course structure exists

A common pattern: build the course once with path 2, then make small edits during the semester with path 1 or 3 — whichever your school makes easier.

Publish 1

Copy & paste into the editor

The fastest way to get one good-looking page into Canvas. No installs, no permissions — if you can edit a Canvas page, you can do this.

Steps

  1. Get the page's HTML source — from a web chat (create with AI) or from any block's HTML view in the Designer.
  2. In Canvas, edit your page and click the HTML editor icon (</> at the bottom-right of the toolbar).
  3. Paste, save, done.

Limits to know about

  • One page per trip. A 24-class course means 24 rounds of copy/paste.
  • Assignment settings — points, due dates, submission types, group weights — can't travel through the editor at all. Path 2 removes exactly this limitation.
Publish 2

Course package import — a whole course in one upload

Canvas can import a full "Course Export Package" (a .imscc file) — that's how courses get copied between semesters. This project builds those packages from your course folder, so one import creates (or updates) everything:

  • Every wiki page, including a designated course home page
  • Every assignment — description, points, due date, submission type, grading type, file-type restrictions, group assignments
  • Assignment groups with percentage weights and drop-lowest rules — your whole grading scheme
  • Week-by-week modules with pages, assignments, text headers, and external links
  • The syllabus

Steps

  1. Build the package — click Build in the Designer, or run: 
    python3 tools/build_imscc.py . -o dist/course.imscc
  2. In Canvas: Settings → Import Course Content → Content Type: "Canvas Course Export Package" → choose your .imscc file → All Content → Import. Canvas finishes in a minute or two.
  3. Spot-check: Assignments (weights under the ⋮ menu → Assignment Groups Weight), a page or two, and Modules.
Re-importing updates, it doesn't duplicate. Every page and assignment gets a stable internal ID. Edit, rebuild, import again — Canvas updates the existing items in place. That's what makes this a management workflow, not a one-time setup.
No special permission required. This uses the same Import Course Content button teachers already use. If your school locks it down (rare), your teaching & learning centre can run the import for you.

Full format reference: tools/README.md · Worked example: tools/example-course

Publish 3

Direct API sync — no import step at all

With a Canvas access token, the canvas_api_sync.py tool pushes a page or assignment straight into your course from the command line: edit a file, run one command, refresh your browser.

First: does your school allow it?

  1. In Canvas, go to Account → Settings and scroll to Approved Integrations.
  2. Look for a "+ New Access Token" button below the table.
  3. Button there? You can use this path — create a token with a purpose and an expiry date, and treat it like a password.
  4. No button? Your institution has disabled self-service tokens (many do). Path 2 covers nearly everything this path does — you lose very little.

Steps

export CANVAS_API_TOKEN="paste-your-token-here"
python3 tools/canvas_api_sync.py my-course \
    --base-url https://canvas.yourschool.edu \
    --course-id 12345

The course ID is the number in your course's URL. Add --only pages/class-3.md to push a single file, or --dry-run to preview what would be sent.

Limits to know about

  • Creates and updates pages, assignments, and the syllabus — but not assignment groups, grade weights, or modules. Do the course structure with path 2 first.
  • Assignments are matched by exact title, so renaming one creates a new one rather than updating. (Path 2 is immune to this.)
  • Test on a sandbox course first, and prefer tokens with an expiry date.
Management

Updating a course in bulk

The package tools work in both directions, which unlocks course-wide edits that would be painful to click through:

  1. Export your existing course: Canvas → Settings → Export Course Content → "Course" → download the .imscc.
  2. Extract it into an editable folder: 
    python3 tools/extract_imscc.py my-export.imscc -o my-course
    Every page and assignment becomes a small text file with its settings at the top.
  3. Edit — visually in the Designer, by hand, or with an agent: "restyle every class page with the Studio Dark theme", "shift all due dates one week later".
  4. Rebuild and import: 
    python3 tools/build_imscc.py my-course
One caveat on the round trip. Extracting an export assigns fresh internal IDs, so importing a rebuilt package back into the same live course creates copies alongside the originals. The round trip shines for populating a new course shell — next semester's section, a sandbox, a redesign. Once a course is managed from a source folder, repeated rebuild-and-import cycles update cleanly in place.
